# Хижина — сайт базы отдыха

Одностраничный сайт с приёмом заявок через Telegram-бот. Две локали (ru/en),
статическая генерация, без базы данных.

- **Стек:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Radix UI
- **Хостинг:** рассчитан на Vercel, но это обычное Node-приложение и запустится где угодно
- **Пакетный менеджер:** pnpm 10

---

## Запуск

```bash
pnpm install
cp .env.example .env.local   # заполнить NEXT_PUBLIC_SITE_URL
pnpm dev                      # http://localhost:3000 → редирект на /ru
```

Команды:

| Команда          | Что делает                                     |
| ---------------- | ---------------------------------------------- |
| `pnpm dev`       | Дев-сервер с горячей перезагрузкой             |
| `pnpm build`     | Продовая сборка                                |
| `pnpm start`     | Запуск собранного приложения                   |
| `pnpm lint`      | ESLint (в Next 16 команда `next lint` удалена) |
| `pnpm typecheck` | Проверка типов без сборки                      |
| `pnpm format`    | Prettier по всему проекту                      |

## Переменные окружения

Полный список — в `.env.example`.

### `NEXT_PUBLIC_SITE_URL` — обязательна на продакшне

**Читается на сборке, а не в рантайме.** Все переменные с префиксом
`NEXT_PUBLIC_` Next вшивает в бандл во время `pnpm build`. Задать её при
`pnpm start` уже поздно: canonical, `sitemap.xml` и OG-теги останутся с тем
значением, что было на билде.

На Vercel переменную нужно завести в настройках проекта **до** первого
продового деплоя, затем пересобрать.

Защита от этой ошибки встроена: если `VERCEL_ENV=production`, а переменной
нет, сборка падает с явным сообщением (`src/lib/site.ts`), а не уезжает
молча на `localhost:3000`.

### `NEXT_PUBLIC_YANDEX_METRICA_ID` — необязательна

Пустое значение = счётчик не подключается вовсе. Так превью-деплои и
локальная разработка не засоряют статистику.

Цели, которые нужно завести в интерфейсе Метрики (тип «JavaScript-событие»),
перечислены в `src/lib/analytics/goals.ts`. Без них видно только просмотры,
но не заявки: форма отправки на сайте отсутствует, лид уходит в мессенджер,
и клик по каналу — последняя точка, где мы вообще видим пользователя.

│       ├── opengraph-image.tsx     превью 1200×630 для мессенджеров
│       ├── error.tsx               граница ошибки, локаль берётся из пути
│       ├── loading.tsx             скелет первого экрана
│       └── privacy/page.tsx        политика конфиденциальности
├── components/
│   ├── analytics/                  Метрика, ссылка с целью
│   ├── booking/                    провайдер, кнопка, попап каналов
│   ├── layout/                     шапка, мобильное меню, футер, CTA-бар
│   ├── sections/                   блоки главной
│   └── ui/                         кнопка, карточка, медиа, модалка
├── i18n/
│   ├── config.ts                   локали, словари
│   └── messages/{ru,en}.json       строки интерфейса
├── lib/
│   ├── analytics/                  цели и отправка событий
│   ├── booking/telegram.ts         сборка deep link
│   ├── content/                    типы и данные сайта
│   ├── legal/privacy.ts            текст политики (не в словарях — см. ниже)
│   ├── seo/jsonld.ts               микроразметка LodgingBusiness
│   ├── site.ts                     единая точка чтения окружения
│   └── utils/                      cn, ссылки на карты
├── assets/fonts/                   вшитые woff2 + статика под OG

Почему текст политики лежит в `src/lib/legal/`, а не в словарях: это документ,
а не строки интерфейса. В общем словаре двенадцать килобайт юридического
текста уезжали бы в клиентский бандл всякий раз, когда словарь понадобится
клиентскому компоненту — например, границе ошибки.

## Правки контента

Пока весь контент — один файл: `src/lib/content/site-content.ts`.
Цены, описания, реквизиты, ссылки на каналы связи. Меняется правкой файла
и коммитом; деплой на Vercel запускается автоматически.

Что ещё ждёт заказчицу — в `content/TODO-CONTENT.md`.

Переезд на CMS обсуждается отдельно, см. `DECISIONS.md`, решение №11.

### Фотографии

Сейчас все блоки рисуют штриховку с подписью «Фото появится позже».
Чтобы подставить настоящий кадр, достаточно указать `image` у объекта:

```ts
{
  id: 'cabin-a',
  name: 'Домик «Лесной»',
  image: { src: '/images/cabin-a.jpg', alt: 'Домик «Лесной» на краю леса' },
  // ...
}
```

Файлы кладутся в `public/images/`. Если картинки будут храниться на стороннем
домене — прописать его в `NEXT_PUBLIC_IMAGE_HOST`, он попадёт и в
`images.remotePatterns`, и в CSP.

## Шрифты

Comfortaa и Nunito подключены **локально** (`src/assets/fonts/`), а не через
`next/font/google`. Причина: `next/font/google` ходит в CDN Google на каждой
сборке, и недоступность CDN роняет билд целиком. Файлы в репозитории делают
сборку воспроизводимой и работающей офлайн.

Оба файла вариативные (ось `wght`), сабсеттнуты до latin + cyrillic, сжаты в
woff2: 39 КБ и 47 КБ на весь диапазон начертаний. Лицензия OFL, копия рядом.

Обновление — вручную из [github.com/google/fonts](https://github.com/google/fonts).

## Деплой

1. Подключить репозиторий к Vercel (пресет Next.js подхватится сам).
2. Завести переменные окружения из `.env.example` для окружения Production.
3. Задеплоить и проверить по чеклисту ниже.

Приложение статическое: все страницы и OG-картинки генерируются на сборке.
Ревалидация и серверные функции не используются.

### После первого деплоя

- `https://домен/robots.txt` — `Allow: /`, а не `Disallow: /`
- `https://домен/sitemap.xml` — продовый домен, не `localhost:3000`
- ссылка на сайт, отправленная в Telegram, разворачивается в карточку с картинкой
- `t.me/Hizhina_booking_bot?start=cabin-a` открывается и бот получает payload
- в Метрике появились хиты и хотя бы одна цель

## Безопасность

Заголовки задаются в `next.config.ts`: CSP, HSTS (только на проде),
`X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`,
`Permissions-Policy`.

В CSP сознательно оставлен `'unsafe-inline'` для скриптов — обоснование
в `DECISIONS.md`, решение №9.
